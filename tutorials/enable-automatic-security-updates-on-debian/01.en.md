## Introduction

Regular security updates are one of the most important basics for running a secure server. In practice, updates are often forgotten, especially on small projects or test systems.

In this tutorial, you will configure `unattended-upgrades` on Debian. This installs security updates automatically, so you do not have to run `apt upgrade` manually every day. At the end, you will also verify that the configuration works as expected.

### What you will have at the end

- Automatic security updates via `unattended-upgrades`
- Daily package list updates via APT periodic tasks
- A tested configuration, including log and timer checks

**Prerequisites**

| Requirement | Description |
|---|---|
| Server | 1 Debian server (for example, a cloud server) |
| Access | A user with `sudo` privileges or direct root access |
| Knowledge | Basic command-line experience |

## Step 1 - Update the server and install required packages

First, update package lists and install the required packages:

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install unattended-upgrades apt-listchanges -y
```

These packages serve the following purposes:

- `unattended-upgrades`: installs updates automatically
- `apt-listchanges`: shows important package changes (for example, news and changelog entries) during upgrades

Then verify that the package is installed:

```bash
dpkg -l unattended-upgrades
```

## Step 2 - Define update origins

The file `/etc/apt/apt.conf.d/50unattended-upgrades` controls which APT origins are used for automatic updates.

Open the file:

```bash
sudo nano /etc/apt/apt.conf.d/50unattended-upgrades
```

Make sure at least the following `Allowed-Origins` entries exist and are not commented out:

```bash
Unattended-Upgrade::Allowed-Origins {
        "${distro_id}:${distro_codename}-security";
        "${distro_id}:${distro_codename}-updates";
};
```

With this setup, Debian installs both security updates and regular package updates from official Debian repositories.

> **Note:** If you only want security updates automatically, keep only `-security`.

Save the file and exit the editor.

## Step 3 - Enable automatic execution

Now enable periodic APT actions and `unattended-upgrades`.

Open:

```bash
sudo nano /etc/apt/apt.conf.d/20auto-upgrades
```

Insert:

```bash
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
```

Meaning:

- `Update-Package-Lists "1"`: refreshes package lists daily
- `Unattended-Upgrade "1"`: runs unattended upgrades daily

Optionally, clean old package cache files automatically:

```bash
APT::Periodic::AutocleanInterval "7";
```

This removes unused downloaded package files every 7 days.

> **Tip:** For production systems, a daily schedule is usually a good baseline. For test systems, this default is often still appropriate.

## Step 4 - Test the configuration

Before relying on automation, run a dry-run:

```bash
sudo unattended-upgrade --dry-run --debug
```

The output should show which origins are used and which packages would be processed.

<details>
<summary>Example: typical dry-run output hints</summary>

```shellsession
Checking if system is running on battery is skipped. Please install powermgmt-base package to check power status and skip installing updates when the system is running on battery.
Starting unattended upgrades script
Allowed origins are: ...-security, ...-updates
No packages found that can be upgraded unattended
```

</details>

If no errors appear, you can run it for real:

```bash
sudo unattended-upgrade --debug
```

## Step 5 - Check logs and timer status

The most important log files are:

- `/var/log/unattended-upgrades/unattended-upgrades.log`
- `/var/log/unattended-upgrades/unattended-upgrades-dpkg.log`

Show the latest log lines:

```bash
sudo tail -n 50 /var/log/unattended-upgrades/unattended-upgrades.log
sudo tail -n 50 /var/log/unattended-upgrades/unattended-upgrades-dpkg.log
```

You can also verify active systemd timers:

```bash
systemctl list-timers --all | grep apt
```

If `apt-daily.timer` and `apt-daily-upgrade.timer` show upcoming runs, automatic execution is active.

> **Important:** If no timers are listed, check whether `systemd` timers are disabled on your system or whether you are using a minimal image without timer defaults.

## Step 6 - Optional: Configure reboot behavior

Some security updates (for example kernel or core library updates) require a reboot. You can control that behavior in `/etc/apt/apt.conf.d/50unattended-upgrades`.

Examples:

```bash
Unattended-Upgrade::Automatic-Reboot "false";
Unattended-Upgrade::Automatic-Reboot-Time "03:30";
```

- With `false`, automatic reboot is disabled.
- With `true`, the system reboots automatically if required, at the configured time.

Plan this carefully to avoid unexpected service interruptions in production.

## Conclusion

You have configured automatic security updates on Debian with `unattended-upgrades`, enabled periodic execution, and tested the setup. This helps reduce the risk of missing critical security patches.

For production environments, it is also recommended to add monitoring and alerting so update failures are detected quickly.

**Quick final checklist:**

- [x] `unattended-upgrades` is installed
- [x] `Allowed-Origins` are set correctly
- [x] `20auto-upgrades` is enabled
- [x] Dry-run was executed without errors
- [x] Timers and logs were checked
